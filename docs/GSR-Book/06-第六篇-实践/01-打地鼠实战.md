# 打地鼠实战：从一条 Kick 看完整 Runtime

现在把前五篇重新装起来。

目标很小：

```text
Alice 进入一局 Battle
地鼠 1 出现
Alice Kick 地鼠 1
得到 Hit=true、Score=1
```

源码位于 `examples/whackmole/`。

## 第一步：定义玩法 Command

玩法 Command 使用自己的区间，不占用 `game` 保留区间：

```go
const (
    StartCommand  gsr.CommandID = 0x04010001
    SpawnCommand  gsr.CommandID = 0x04010002
    ExpireCommand gsr.CommandID = 0x04010003
    KickCommand   gsr.CommandID = 0x04010004
    FinishCommand gsr.CommandID = 0x04010005
)
```

玩法 payload 是普通值：

```go
type KickRequest struct {
    Player game.PlayerID
    Shrew  uint64
    Epoch  game.BattleEpoch
}

type KickResult struct {
    Hit    bool
    Score  int64
    Reason string
}
```

Epoch 来自客户端已知的 Battle 代际，用于拒绝旧局输入。

## 第二步：实现 BattleLogic

```go
type whackMoleLogic struct {
    seed     uint64
    next     uint64
    shrews   map[uint64]ShrewState
    scores   map[game.PlayerID]int64
}
```

它没有 Runtime 指针，也没有 mutex。所有调用都来自 Battle Mailbox。

BattleService 将保留 Command 之外的消息直接交给 Logic。Logic 在 `HandleBattle` 中用直观的 `switch` 分发玩法 Command。

## 第三步：Start 生成第一只地鼠

```go
func (l *whackMoleLogic) HandleBattle(
    ctx game.BattleContext,
    command gsr.Command,
) error {
    switch command.ID {
    case StartCommand:
        if err := l.spawn(ctx); err != nil {
            return err
        }
        return ctx.Reply(struct{}{})
    // ...
    }
}
```

`ctx.Reply` 可以直接调用。Start 由 Send 到达时，它是成功无副作用；如果未来测试改用 Call，也能得到结果。

## 第四步：用 Timeline 调度过期

```go
func (l *whackMoleLogic) spawn(ctx game.BattleContext) error {
    l.next++
    id := l.next
    l.shrews[id] = ShrewVisible

    _, err := ctx.Timeline().After(
        time.Second,
        ExpireCommand,
        ExpireRequest{
            Shrew: id,
            Epoch: ctx.Epoch(),
        },
    )
    return err
}
```

Timer 到达时仍经过 Battle Mailbox。Expire 还要检查当前 ShrewState 和 Epoch，旧事件不能重复修改分数。

## 第五步：Kick

核心逻辑：

```go
case KickCommand:
    request, ok := command.Payload.(KickRequest)
    if !ok {
        return game.ErrInvalidCommand
    }
    if request.Epoch != ctx.Epoch() {
        return ctx.Reply(KickResult{
            Score:  l.scores[request.Player],
            Reason: "stale_epoch",
        })
    }
    if l.shrews[request.Shrew] != ShrewVisible {
        return ctx.Reply(KickResult{
            Score:  l.scores[request.Player],
            Reason: "not_visible",
        })
    }
    l.shrews[request.Shrew] = ShrewHit
    l.scores[request.Player]++
    return ctx.Reply(KickResult{
        Hit:   true,
        Score: l.scores[request.Player],
    })
```

第二次 Kick 同一只地鼠不会再次得分。

## 第六步：组合根创建 Battle

`main.go`：

```go
runtime := gsr.NewRuntime(gsr.Config{
    NodeID:  "whackmole",
    Workers: 2,
})
defer runtime.Close(context.Background())

battle, err := game.NewBattleService(game.BattleConfig{
    ID: "battle-42",
    Participants: []game.Participant{{
        Player: "alice",
    }},
    Logic: newWhackMoleLogic(7),
})

battleRef, err := runtime.CreateService(gsr.ServiceSpec{
    Service: battle,
})
```

## 第七步：Send 启动，Call 输入

```go
func startWhackMole(
    runtime game.CommandRuntime,
    battle gsr.ServiceRef,
) error {
    if err := runtime.Send(
        battle,
        game.StartBattleCommand,
        struct{}{},
    ); err != nil {
        return err
    }
    return runtime.Send(battle, StartCommand, struct{}{})
}
```

随后：

```go
value, err := runtime.Call(
    context.Background(),
    battleRef,
    KickCommand,
    KickRequest{
        Player: "alice",
        Shrew:  1,
        Epoch:  1,
    },
)
```

同一目标 Mailbox 保持接受顺序，因此两个 Start 在后续 Kick 前执行。

运行：

```bash
go run ./examples/whackmole
```

## 第八步：Finish 与 Wallet

玩法把分数冻结为结算意图：

```go
return ctx.Finish(game.FinishBattle{
    RequestID: "finish-42",
    Settlements: []game.SettlementIntent{{
        RequestID: "settle-42",
        Currency:  "coin",
        Entries: []game.SettlementEntry{{
            Player: "alice",
            Delta:  game.Amount(l.scores["alice"]),
        }},
    }},
})
```

BattleService 负责状态机和 Wallet 协作，Logic 不接触 LedgerStore。

## 第十步：基准

```bash
go test ./examples/whackmole \
  -run '^$' \
  -bench '^BenchmarkKick' \
  -benchmem \
  -count=3
```

`BenchmarkKickSingleBattle` 测一个 owner 的连续 Call；`BenchmarkKickAcrossBattles` 用 64 个独立 Battle 和 4 个 worker 测分片。

它们没有覆盖真实网络和 Wallet I/O。基准名称必须诚实描述测了什么。

## 这一例没有做什么

- 没有生产房间 Factory；
- 没有真实客户端协议；
- 没有持久 LedgerStore；
- 没有自动扩容；
- 没有用 goroutine 并行同一局；
- 没有把一次基准数字当容量承诺。

## 本章小结

一条 Kick 看起来只是一次加分，背后却验证了 GSR 最重要的结构：

```text
ServiceRef 寻址
Mailbox 串行
Send/Call 意图
BattleContext 权限
Timeline fencing
RequestID 结算
Runner 隔离 I/O
Snapshot / Record / Replay
```

这就是纵向切片的价值：不是演示某个 API，而是让一条真实业务流穿过所有边界。
